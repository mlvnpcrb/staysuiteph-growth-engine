## Engine contract under development

The extension installs an isolated message bridge only in the explicitly connected dashboard tab, using existing optional host permissions. Page requests contain only an owned saved job identity/revision/digest and the reviewed public actor. Authentication cookies, Facebook session context and media bytes never travel through window messages. Background checks sender extension/frame/tab/origin, connection generation, current StaySuite owner and fresh Facebook actor. A session-scoped run record binds the exact reviewed input and connection generation. Duplicate retries acknowledge the same run; another active queue is refused. No engine tab is created or focused.

The extension service worker rechecks and approves the exact saved version, verifies Direct profile readiness, then uses existing claims, pacing and receipt reporting. Chrome alarms wake one operation at a time at the server eligibility timestamp, with a periodic watchdog. An existing claimed target after worker interruption is paused for outcome review and is never automatically submitted again. First-profile validation is not bypassed. Compose progress comes from authenticated backend receipts, not from queue-start acknowledgement. A pause cannot undo a submission already in flight. Ambiguous outcomes require explicit review.

Native tests must verify text, photos and every newly added publishing format against actual Facebook behavior before those paths can be described as fully matched. The owner selects and approves the exact test post and eligible group in the app; no unspecified test post is authorized.

## Extension distribution

The reference ZIP includes the Chrome Web Store `update_url` (`clients2.google.com/service/update2/crx`). StaySuite currently distributes unpacked builds, so updates are manual. An initial Chrome Web Store submission (unlisted is an option) is required for normal automatic updates. No store listing or publication has been created during this work.

## Implementation notes for remaining contracts

- The current Compose draft defaults to an additional 15-minute interval, while the ZIP defaults to a pause after every 1 post of 2 minutes. This is a real functional mismatch. Do not fix it with labels alone: align persisted eligibility, fractional/zero pause values, pacing and run review. Preserve legacy campaign behavior for existing saved jobs.
- Multiple templates, spintax and random media need frozen per-operation content. Resolve choices before final approval, and bind the exact text/media/post order to server snapshots. Never choose unreviewed replacement content in the publisher.
- Introduce a versioned plan for additional per-target content/format fields. Old extensions currently parse only plan version 1; a new version must fail closed there, preventing an old client from stripping new fields and publishing the wrong base text. Keep old approval hashes unchanged when the new fields are absent.
- Audit the ZIP's sequential/alternate/rotate semantics before defining the operation matrix; do not assume one target per unique group is sufficient when multiple templates are selected.
- Facebook backgrounds, Pages and first-comment requests change the actual publishing contract. Add separate adapter/version readiness and fixture coverage; do not inherit an unrelated live compatibility check. A successful post with a failed/uncertain first comment must retain its post receipt and never cause a duplicate story retry.
- The reference Card control opens a manual Words/Look/Brand editor backed by its card engine, supports square/portrait/landscape output, local brand kits, remix/sets/download, and attaches a generated image. Recreate behavior in original StaySuite code; do not import the vendor runtime. AI writing is excluded.

## Background queue operating limits

- Keep the connected, signed-in StaySuite dashboard and an existing signed-in Facebook tab open. The current adapter reuses that Facebook tab without changing its URL or focus; it does not support closing all Facebook tabs.
- No new manifest permissions, offscreen documents, vendor services or credentials were added. Browser session run records contain only job identities and routing metadata, not Facebook credentials or post media.
- The Post Now click authorizes the exact content and target snapshot; there is no additional Compose approval-plan page. A profile still requires the separate first-use Direct compatibility validation before bulk publication is enabled.
- Runs do not automatically resume across a full browser restart or a replaced connection. Review saved receipts and uncertain claims before explicitly restarting. Chrome alarms can run later than requested; server-side eligibility prevents an early post.
- Fixture verification covers five groups, interval waits, duplicate requests, another active run, unvalidated profiles, changed accounts, paused queues and uncertain outcomes. It is not a live Facebook acceptance result.
